# AI 漫剧前期生产

目标不是写一份好看的提示词，而是交付一套下游可以稳定生图和做视频的生产包。

## 核心约束

- 原文是叙事事实源。把每项信息标为“原文明确 / 原文推断 / 改编设计”；后两者不能伪装成原文。
- 先拆解全文，再设计资产，再写分镜。不得边读边生成，避免后文状态推翻前面的资产设计。
- 资产使用全项目稳定 key。镜头只通过 key 引用；名称变化、版本更新不能改变 key。
- 已确认资产不可变。返修创建新版本；没有用户明确授权，不覆盖、裁切或清除已确认资产。
- 角色母版只锁身份，表情、姿态、服装/伤势状态、人与道具接触关系均为派生资产。
- 全身四视图只锁定体型、服装和整体轮廓，不能单独承担面部一致性；角色进入表情、动作或剧情图生产前，必须补齐面部身份控制包并确认。
- 表情与姿态必须来自可定位原文中的具体时空、行为、接触物、光源和前后状态；禁止脱离剧情用“疲惫、震惊”等抽象词凭空生成摄影棚表情包。
- 每镜必须具有原文证据、具体场景、起始态、结束态、连续性和非空资产引用。
- 多文件资产必须由镜头选择具体文件或状态，不允许默认取第一张。

## 工作流

1. 改编小说时，完整阅读 [原文拆解](references/source-breakdown.md)，建立覆盖台账。
2. 设计或补全人物、场景、道具与特效时，阅读 [资产圣经](references/asset-bible.md)。
   角色派生资产开工前，先确认全身四视图、面部身份控制包与半身衔接母版；生成时把身份、姿态/构图、场景和风格参考分别标注用途。
3. 生成或返修任何角色、表情、姿态、场景合成或分镜图片时，完整阅读 [参考图生图规范](references/reference-image-generation.md)。先列参考职责与主次、不变量和本轮唯一允许变量，再按身份→姿态/构图→场景道具→光色逐层生成；失败稿不得绑定或进入下一轮参考。
4. 写分镜、首帧或视频提示词时，阅读 [逐镜生产包](references/shot-package.md)。
5. 审核、导出、注入图片或开工时，阅读 [质量闸门](references/qa-gates.md)。

## 最低交付

- 原文覆盖台账：重要段落均有去向，未采用内容明确说明原因。
- 资产圣经：每项有 key、分类、层级、事实等级、证据、锁定段、交付件、依赖、优先级和 used-by。
- 分镜表：每镜有起止状态、镜头职责、资产引用、首帧提示词、运动提示词与验收标准。
- 代表关键帧：先验证高风险角色、场景、核心道具和接触动作，通过后才批量生产。
